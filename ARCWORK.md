# Learnings

- `new URL()` normalizes `../` path segments away, so SSRF-safe code must check for `..` in the raw input string (before relying on URL class behavior).
- Build/test command: `npx tsc --noEmit` for typecheck; `node --experimental-sqlite --no-warnings --import tsx --test tests/*.test.ts` for test suite.
- The existing project uses z.union discriminants in schemas (`markdown`, `url`, `name`) to differentiate input variants — no special discriminator key needed since Zod matches sequentially.
- Run results are built from recorded events, never model prose (`src/lib/runs/report.ts`). A code run reports `files_changed` (+added/-removed), `commands_run`, `commits_made_by_this_run`, `tests_status` from tool events. A change request with zero successful edit/write ends as status `no_changes`, not `done`. Commit hashes the run did not create, and files named in "changed" claims with no recorded edit, are stripped from the summary. In local mode `git rev-parse HEAD` and `git status --porcelain` are recorded at the start (`options.gitBaseline`) and compared at the end; a moved HEAD or untouched files that changed add an `external_changes_detected` warning and are never attributed to the run.
- New terminal run statuses: `no_changes`, `stalled`, `partial` (plus the old `done`, `error`, `cancelled`). Use `isTerminalStatus` / `TERMINAL_STATUSES` from `src/lib/runs/repo.ts`; do not list statuses by hand. The status column is plain TEXT, so no migration. The saved report lives in `run.options.report`, the cross-segment record in `run.options.record`.
- Stall guard (`src/lib/agent/stall-guard.ts`): after 25 tool calls with no edit the model gets a firm "make your first edit now" note listing files read; after 50 the run ends as `stalled`. Repeat reads of an unchanged range return a short "already read" note. Off in plan mode and for prompts that do not ask for changes. The counter carries across resumed segments (`options.stepsSinceEdit`). Two segments with no edit also end as `stalled` (`pauseOutcome`).
- Hitting `MAX_SEGMENTS` ends as `partial` (files so far, remaining todo, `git diff --stat`), continuable with `send_feedback`; it is no longer an `error`. `start_task` states the time cap and warns when measured steps/min of the model (from past runs, `estimate.ts`) will not fit the step budget.
- `get_task_status` is compact: one short line per event (tool + main arg, first result line), never file contents; always shows files changed, edits_count, tests_status, steps_since_last_edit, segments_used, warnings. `wait_seconds` may be up to 300 (default stays 45; only raise it if the MCP client allows long tool calls). `detail="full"` still returns everything.
- Failed `edit_file` ("old_string not found") returns the nearest real lines with numbers (`edit-hints.ts`); after 2 failures on a file it points to `replace_lines(path, start, end, new_text)` or `write_file`. After every local edit of .js/.json/.ts/.tsx/.jsx the file is parse-checked (syntax only, project's own `typescript`, silent when absent) and the error comes back in the same tool result.
- Local runs hash each file when read; if it differs just before an edit/write, the edit is held back, an `external_change` event is emitted, the fresh file is returned, and the model re-applies its change on top of the other person's. No lock file is written (hash detection is enough and writes nothing into the repo).
- A brief with 3+ labelled fixes (`FIX 1:`, `1)`) or 6+ named files runs as sequential sub-tasks (`multi-fix.ts`): own conversation and step budget per fix, named files read first, one result line per fix built from recorded edits. Pause state is kept in `run.options.subtasks`. Write multi-fix briefs with `FIX n:` labels and put acceptance text under an `ACCEPTANCE:` heading so it is repeated for every fix.
- Eval tasks may set `maxStepsToFirstEdit` and `maxSteps` in task.json (`multi-fix-8-files` uses 30 and 75); `scripts/eval-agent.ts` fails a task whose first edit comes later. Deterministic incident replays live in `tests/incident-replays.test.ts`.
- macOS gotcha: `sed -i` needs an empty-string backup arg, and a failed sed in a chained command can silently leave a test unfixed: run the tests again before committing.
- Bridge sleep/wake (`desktop/bridge-core.js`): a Mac that sleeps leaves a dead TCP connection that never errors, so the long-poll used to hang forever and the server marked the computer offline. Now every request has a deadline (poll 35s, result 30s), a clock-jump watchdog aborts the in-flight poll on wake, and command results are retried (4 times, backoff) instead of being dropped. Client-side only: the bridge protocol is unchanged. Covered by `tests/bridge-sleep.test.ts` (a fake server that hangs or kills sockets).
